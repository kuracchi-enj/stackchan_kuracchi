# v0.0.1：自作の最小プログラムをK151実機で確認

記録日：2026-11-08。対象コミット：`dc42198281fb1c32eb6d915ebd1cf0d1ad171d2b`（PR #3のマージ）。

この版では、StackChanの標準プログラムを自作の最小C++プログラムに置き換え、画面とLEDが安定して動くことを確認した。これから表示や反応を一つずつ変えていくための出発点になる。

`v0.0.1`はこのプロジェクトの版名。本体に表示される文字列は`Minimal offline v0.1`のままで、画面表示の版番号とは分けて扱う。この文書の追加コミットは対象コミットより後に作るため、タグの対象にこの文書自体は含まれない。

## ここまでに行ったこと

### 1. カスタマイズの進め方を決めた

Arduino/C++で基本動作を作り、同じ動作をPicoRubyで再現し、その後にMQTTでAWS上の自前MCPサーバーへ接続する3段階の[計画](../superpowers/plans/2026-10-31-stackchan-customization.md)を作成した。実機の表示・動作、通信、AWS上の処理は、それぞれ分けて確認する。

### 2. 開発環境と最小プログラムを用意した：PR #1

Mac内のプロジェクト専用フォルダにArduino CLIと必要なライブラリーを用意した。C++のコードを本体用プログラムへ変換する処理をスクリプト化し、使う版を固定した。

| 部品 | 使用した版 |
| --- | --- |
| Arduino CLI | 1.5.1 |
| M5Stackボード定義 | 3.2.2 |
| M5StackChan | 1.1.1 |
| M5Unified | 0.2.21 |
| M5GFX | 0.2.28 |

対象はK151、チップはESP32-S3、Flashは16MB。ビルドにはCoreS3向けの設定`m5stack:esp32:m5stack_cores3`を使用した。再現手順は[開発環境](../toolchain.md)、版とチェックサムは[環境の記録](../../config/toolchain-lock.json)に残した。

[最小プログラム](../../firmware/arduino/minimal_offline/minimal_offline.ino)は、起動画面の表示と、弱い青色LEDの点滅を行う。サーボ（首を動かすモーター）の電源には無効化命令を送り、位置を変える命令は送らない。Wi-Fi・BLE・マイク・カメラ・音声再生を使う処理は含めていない。

### 3. 通信失敗を正常と取り違える判定を修正した：PR #2

PR #1のCopilotレビューで、サーボ電源の設定を読み戻す際、通信失敗を「OFF設定を確認できた」と取り違える可能性が見つかった。

通信が成功したことと、OFF設定になっていることを別々に確認するよう修正した。読み取りに失敗した場合やON設定が返った場合は、準備完了としない。Mac上で通信を模擬し、読み取り失敗・正常なOFF・異常なON・無関係な出力だけがONの4ケースを確認した。

### 4. 書き換え前の状態とバックアップを確認した

ユーザーが型番K151と標準状態での顔表示を確認し、StackChan Worldとの紐付けを解除した。

Macアプリ版M5BurnerはOSのセキュリティ警告を受けて起動を中止した。保護設定を解除する操作は行っていない。代わりに`esptool`を使い、本体のESP32-S3側のFlash全体をバックアップした。

USBハブ経由の高速転送では通信エラーが出たため、115200bpsで読み取った。最初の読み取り後の再起動で設定・起動管理領域に差が生じたため、その領域を再取得して別の復旧用ファイルを作成し、本体全体との一致を確認した。元の保存ファイルも保持した。経緯と戻す操作は[復旧手順](../recovery.md)に記録している。

バックアップは紐付け解除後の内容であり、解除前の会話履歴やクラウド側の紐付けを復元するものではない。バックアップから実際に書き戻す復旧実演は未実施。

### 5. 本体へ書き込み、初回動作を確認した：PR #3

Arduino CLIで115200bps・全フラッシュ消去なしの書き込みを実施した。ボード設定の記録にある既定速度921600bpsに対し、この実機への転送では115200bpsを指定した。

## 確認できたこと

ツールで確認した結果と、人が本体を見て確認した結果を分けて記録する。

| 確認方法 | 確認した内容 | 結果 |
| --- | --- | --- |
| Mac上のビルド | CoreS3向けにプログラムを変換できる | 終了コード0。依存コードの警告は[検証記録](../verification/phase1.md)に記載 |
| Mac上の回帰テスト | 初期化判定の正常・異常系4ケース | 4ケース成功 |
| 読み取り・比較ツール | 復旧用の16,777,216バイトと本体Flash全体の一致 | 一致を確認 |
| 書き込みツール | 本体へプログラムを転送できる | 終了コード0。転送した4領域すべてでハッシュ一致 |
| ユーザーの目視 | 起動画面 | `Minimal offline v0.1`・`Offline ready`・`Servo power: OFF cmd`を確認 |
| ユーザーの目視 | LED | 弱い青色で約0.5秒ごとに点灯・消灯 |
| ユーザーの観察 | 首の動き・異音・発熱 | 勝手な首の動き、異音、異常な発熱なし |
| ユーザーによる電源操作 | 電源を切って入れる操作を3回 | 毎回同じ表示とLEDに戻り、異常なし |
| ユーザーによる継続観察 | 10分間の動作 | 同じ表示と点滅が継続。勝手な再起動や異常なし |

サーボ電源は無効化命令と設定の読み戻しまで確認した。`Servo power: OFF cmd`はその状態を示す表示であり、実際の供給電圧を測定した結果ではない。

詳細は[段階1の検証記録](../verification/phase1.md)、[初回書き込み記録](../verification/minimal-upload.json)、[初回ビルド記録](../verification/minimal-build.json)を参照。ビルド記録の実機未確認という項目は2026-11-07時点の記録であり、翌日の書き込み・実機確認は別の記録に残している。

## この版に含めていないもの

- LEDの色を変更する次のカスタム、タッチ入力、表情の切り替え、首を動かす機能。
- バックアップや公式配布ファームウェアからの復旧実演、サーボ供給電圧の測定。
- PicoRuby版の実装・書き込み・実機確認。
- MQTT通信、AWSへのデプロイ、自前MCPサーバーへの接続。

初回の最小プログラムの合格条件は確認できたが、タッチ・表情・首の動きや復旧を含む段階1全体は途中の状態。

## 公開する情報の範囲

公開するのはソースコード、手順、機密情報を取り除いた検証結果に限る。バックアップ・生ログ・実機の識別情報はMac内の非公開フォルダで保持する。Wi-Fi設定・秘密鍵・証明書・AWS認証情報・MCPの認証トークン・録音・写真を公開リポジトリへ含めない。

次はLEDの色を一つ変え、「コード変更→ビルド→USB書き込み→実機で変化を確認」の流れを試す。
