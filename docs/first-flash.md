# 最初に入れる最小プログラム

この手順は本体が手元に戻ってから使う。実物の型番、初期状態、復旧用ファームウェアの確認が終わるまでは書き込まない。

## 今回のプログラムで確認すること

`firmware/arduino/minimal_offline/minimal_offline.ino`を使う。

- 画面に`Minimal offline v0.1`と起動状態を表示する。
- 台座の12個のLEDを、低い明るさの青で0.5秒ごとに点灯・消灯する。
- サーボ電源を無効にする命令を送り、首の位置を変える命令は送らない。
- Wi-Fi・BLE、標準AI会話、スマホ連携、マイク・カメラ・音声再生を起動しない。

画面上の`Servo power: OFF cmd`は、無効化命令を送ったという表示。電源が物理的に切れたことの測定結果ではない。実機で意図しない首の動きがないことを確認する。

## 先に確認するもの

- [ ] [実機の初期状態](device-baseline.md)の確認ができている。
- [ ] アカウントに紐付け済みなら、標準ファームウェアが動くうちに解除している。
- [ ] [復旧手順](recovery.md)に沿って、実機に対応する公式ファームウェアを確保している。
- [ ] USBケーブルが充電専用ではなく、データ通信に対応している。
- [ ] 本体がM5Stack製StackChan完成品である。CoreS3単体や別の自作機へ流用しない。

## 本体へ書き込むとき

1. 台座側のUSB-CポートでMacへつなぐ。首やケーブルが引っ掛からないように置く。
2. `./scripts/arduino.sh board list`でポートを確認する。抜き差しで増減するポートを対象にする。
3. `./scripts/build-minimal.sh`でビルドする。
4. 対象ポート・型番・復旧準備を確認したうえで、Arduino CLIの`upload`からビルド済みの最小プログラムを書き込む。実際のポートがわかってから、その機器向けのコマンドを作る。
5. 再起動後の画面とLEDを確認する。首が動く、異音がする、熱くなる場合は本体の電源を切る。USBを抜くだけでは電池で動き続ける。
6. `BASE INIT FAILED`が出た場合は電源を切る。台座側のI/O拡張との通信に失敗しており、サーボ電源の状態も確認できていない。

最初に全フラッシュの消去を行うコマンドは用意しない。新しいプログラムを起動することと、古い設定やクラウド側の履歴を消すことは別の作業。以前のWi-Fi情報などが保存領域に残る可能性は、設定削除の段階で確認する。

## 初回の合格条件

- [ ] 画面に最小プログラムの名前が出る。
- [ ] LEDが低い明るさで青く点滅する。
- [ ] 首が意図せず動かず、異音や異常な発熱がない。
- [ ] 電源を入れ直して3回とも同じ表示になる。
- [ ] 10分間で異常な再起動がない。

次の変更は、LEDの色を一つ変えること。その後、画面タッチに反応する処理を追加する。サーボ動作の追加は、原点と動作範囲を確認してから行う。

## この初期化方法を選んだ理由

公式BSPの`M5StackChan.begin()`はサーボ電源を有効にし、サーボ初期化も実行する。最初は画面とLEDを確認したいため、その一括初期化を呼ばず、公式BSPに含まれるI/O拡張ドライバーで台座を初期化する。

台座のピン番号や通信方法はソースにまとめ、普段の作業ではビルドと表示確認だけを行う。実機動作を保証するものではないため、最初の確認は机上で行う。

参照：[公式BSPの初期化処理](https://github.com/m5stack/StackChan-BSP/blob/main/src/M5StackChan.cpp)、[I/O拡張ドライバー](https://github.com/m5stack/StackChan-BSP/blob/main/src/drivers/PY32IOExpander/PY32IOExpander.hpp)。
