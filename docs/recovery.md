# 公式ファームウェアへ戻す手順

対象はM5Stack製StackChan完成品。2026-11-08にユーザーが実物の型番K151を確認した。実際に書き込むときも、対象機器とポートの一致を確かめる。

この手順は公式資料で確認した操作。復旧そのものはまだ実機で試していない。

書き込み前に用意する復旧用ファイルは、対象機の公式配布ファームウェアか、読み取り完了を検証した元の実機の全体バックアップとする。ファイルの確保と、実機での復旧成功は別に確認する。

2026-11-08、本環境では公式配布のMacアプリ版M5Burnerに対してOSのセキュリティ警告が出たとユーザーが報告した。取得したアプリにコード署名が付いていないことも確認し、起動を中止した。警告の正確な文面と原因は未確定で、誤検知や安全性を断定しない。保護設定を無効化して起動する手順は使わない。

代替候補の[公式Web版のStackChan-UserDemo](https://burner.m5stack.com/?firmware=1897200000000002129)では、公開者`m5stack`、表示版`1.6.0`、WebSerialを使う書き込み画面を確認した。これはWeb版の提供版であり、手元の実機に入っている版を読み取った結果ではない。ブラウザからの復旧、ファームウェアファイルの保存は未実施。候補を見つけたことだけで復旧準備完了とは扱わない。

## 公式配布ファイルを使う準備

1. [StackChan公式資料](https://docs.m5stack.com/en/StackChan#restore-factory-firmware)から、Mac用M5Burnerを入手する。
2. M5Burnerで`StackChan`を検索し、`Only Official`で対象を絞る。
3. 実物に対応する公式ファームウェアをダウンロードする。名前と版は確認後に記録する。現時点では復旧用ファームウェアを確保済みとは扱わない。
4. 標準アプリに紐付け済みなら、本体の設定かスマホアプリで解除する。公式資料では、解除でAI設定と会話履歴が削除され、スマホ連携が切れると案内されている。
5. 本体の型番、標準ファームウェア版、確認できる原点・校正情報を控える。個体情報を含む控えやバックアップは`private/`など公開しない場所に保存する。

## 実機のバックアップを使う代替経路

M5Burnerを利用できない場合は、書き換える前の実機から読み出したフラッシュ全体を、元のプログラムへ戻すためのファイルとして確保する。これは公式サイトから配布ファイルをダウンロードする方法とは別。対象機のESP32-S3に内蔵・接続された16MBのフラッシュが対象で、台座の別の制御チップやサーボ内の保存情報まで取得するものではない。

1. 型番・チップ・フラッシュ容量・保護状態を確認する。本環境ではESP32-S3と16MB、Secure BootとFlash Encryptionが無効であることを読み取り確認した。保護設定の変更は行わない。
2. Arduino用ボード定義に同梱される`esptool`の`read-flash`で、アドレス`0x0`から`0x1000000`バイト（16MiB）を`private/backups/`へ読み出す。通常より時間がかかるため、今回安定して読めた115200bpsを使う。取得・比較時は`--after no-reset`で標準プログラムの再起動を避け、続けて比較する場合も`--before no-reset`を使う。標準プログラムが起動して設定を更新すると、比較時点の内容に差が生まれる可能性がある。
3. 読み取りの終了コード0、ファイルの大きさ16,777,216バイト、ファイルのハッシュを確認する。必要に応じて、書き換え前に`verify-flash`で本体とファイルの一致を確認する。`verify-flash`は比較する操作で、書き込む操作ではない。
4. 復旧が必要になったときは、同じ実機・ポート・容量・保護状態を確認し、`esptool`の`write-flash`で元のバックアップをアドレス`0x0`へ戻す。この操作は保存範囲を上書きするため、復旧が必要な場面だけで行う。
5. 転送結果の検証に加えて、実機の再起動と標準画面を確認する。それまでは復旧成功としない。

バックアップにはWi-Fi設定などが残っている可能性がある。所有者だけが読めるファイルとしてMac内に保存し、公開リポジトリや外部サービスへアップロードしない。今回の取得はアカウントの紐付け解除後なので、解除前の会話履歴やクラウド側の紐付けを戻すものではない。

2026-11-08、全体読み取りの終了コード0と16,777,216バイトの保存を確認した。最初の読み取り後に標準プログラムが再起動し、後の比較でNVSとOTA管理領域内の差が見つかった。静的領域8区間が一致することを確認したうえで、標準プログラムを起動させずに設定・起動管理の領域だけ再取得し、最初の全体保存を元に別の復旧用ファイルを作成した。そのファイルは`verify-flash`で本体全体との一致を確認した。元の全体保存は上書きせずに保持している。

この経路での復旧は未実施。ファイルの取得・比較に成功したことと、復旧操作を実機で確認できたことは別に記録する。

参照：[Espressifの読み書き・検証コマンド](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/esptool/basic-commands.html)。

## M5Burnerで戻す操作

1. 本体を机に置き、首の周囲とUSBケーブルに余裕を持たせる。
2. データ通信対応USB-Cケーブルで、Macと本体の台座側ポートをつなぐ。
3. 電源を入れ、M5Burnerで対応する公式ファームウェアの`Burn`を選ぶ。
4. ケーブルの抜き差しで増減したポートを選ぶ。他の機器へ書き込まない。
5. ポートが出ない場合は、公式の操作動画と実機を照合する。RSTは台座の底面ではなく、画面のあるメインユニット側のmicroSDスロット付近にある。ボタンを特定できた場合だけ約3秒押し、横のインジケーターが緑になったら離す。見つからなければ別のボタンや穴を押さず、接続方法を確認し直す。
6. `Start`を選び、完了表示までケーブルを抜かない。
7. 再起動後、標準画面・電源・LEDを確認する。首は周囲に注意して小さな動作から確認する。

## 何が戻るか

公式ファームウェアを入れ直すことと、以前の設定や履歴を完全に復元することは別。Wi-Fi情報、アカウントの紐付け、履歴、校正値が以前の状態に戻るとは保証しない。

本プロジェクトでは、最初に本体のフラッシュ全体を空にする作業を行わない。カスタム版への書き換えと、不要な設定・サービス連携の削除は別に扱う。保存済みの情報を消去するときは、対象領域を確認してから行う。

USBを抜いても電池で動くため、停止が必要なら本体の電源操作を使う。
