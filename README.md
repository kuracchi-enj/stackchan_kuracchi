# StackChanカスタマイズ

届いたStackChanを、Arduino/C++、PicoRuby、AWSとのMQTT連携の順にカスタマイズするプロジェクト。

ハードウェア初心者でも、一つずつ動作を確かめながら進められる構成にする。

## 最初に読むもの

- [カスタマイズ計画・初版](docs/superpowers/plans/2026-10-31-stackchan-customization.md)：全体像、作業手順、完了条件、復旧、安全対策。
- [調査メモ](docs/research/2026-10-31-stackchan-feasibility.md)：公式資料、PicoRuby移植の対応状況、確認できていない点。
- [最初の書き込み手順](docs/first-flash.md)：画面とLEDだけの最小プログラムを試す手順。
- [開発環境](docs/toolchain.md)：このプロジェクト内だけに用意するビルド環境。
- [実機の初期状態](docs/device-baseline.md)と[復旧手順](docs/recovery.md)：本体が手元に戻ったときの確認事項。

## 進める順番

| 段階 | 作るもの | 主に使うもの |
| --- | --- | --- |
| 準備 | 機種確認と、元のファームウェアに戻す手順 | 公式資料、M5Burner |
| 1 | タッチで表情・LED・首の動きが変わる | Arduino IDE、C++、M5StackChan |
| 2 | 同じ動作をPicoRubyで作る | stackchan-picoruby、R2P2-ESP32 |
| 3 | タッチからAWS上のMCPツールを呼び、結果を表情で示す | MQTT、AWS IoT Core、Lambda、MCPクライアント |

機種はM5Stack製のStackChan完成品を仮定している。実物の型番はまだ確認していない。

PicoRuby移植版のREADMEでは、Wi-Fi・HTTP・MQTTは未接続とされている。段階3には通信機能の検証と、必要ならCによる通信部分の追加を含める。PicoRuby対応が、そのままAWS接続までの対応を意味するわけではない。

## 現在の状態

2026-11-07、標準のAI会話・スマホ連携を引き継がず、自作の最小プログラムへ置き換える方針で準備を開始した。最初に本体の保存領域を丸ごと消す工程は設けない。

現在は本体が手元にないため、実物の型番確認・初期状態の確認・書き込みは未実施。用意した最小プログラムは、画面と低輝度LEDの点滅を確認するもので、サーボ電源には無効化命令を送る。ビルドと実機確認の状況は[検証記録](docs/verification/phase1.md)に分けて残す。

CoreS3向けのコンパイルは成功した。本体の画面表示・LED点滅・サーボ電源の状態は、実機が手元に戻ってから確認する。

AWSへのデプロイとMCPサーバーへの接続も未実施。
