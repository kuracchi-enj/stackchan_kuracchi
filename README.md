# StackChanカスタマイズ

届いたStackChanを、Arduino/C++、PicoRuby、AWSとのMQTT連携の順にカスタマイズするプロジェクト。

ハードウェア初心者でも、一つずつ動作を確かめながら進められる構成にする。

## 進める順番

| 段階 | 作るもの | 主に使うもの |
| --- | --- | --- |
| 準備 | 機種確認と、元のファームウェアに戻す手順 | 公式資料、esptool、M5Burner（利用可能な場合） |
| 1 | タッチで表情・LED・首の動きが変わる | Arduino IDE、C++、M5StackChan |
| 2 | 同じ動作をPicoRubyで作る | stackchan-picoruby、R2P2-ESP32 |
| 3 | タッチからAWS上のMCPツールを呼び、結果を表情で示す | MQTT、AWS IoT Core、Lambda、MCPクライアント |

対象はM5Stack製のStackChan完成品。2026-11-08にユーザーが実物の型番K151を確認した。

PicoRuby移植版のREADMEでは、Wi-Fi・HTTP・MQTTは未接続とされている。段階3には通信機能の検証と、必要ならCによる通信部分の追加を含める。PicoRuby対応が、そのままAWS接続までの対応を意味するわけではない。

## 現在の状態

2026-11-07、標準のAI会話・スマホ連携を引き継がず、自作の最小プログラムへ置き換える方針で準備を開始した。最初に本体の保存領域を丸ごと消す工程は設けない。

2026-11-08、ユーザーがK151での顔表示とStackChan Worldとの紐付け解除を確認した。MacからESP32-S3と16MB Flashを読み取り確認し、非公開の復旧用バックアップと本体全体の一致を確認した。その後、最小プログラムを115200bps・全フラッシュ消去なしで書き込み、転送した4領域のハッシュ一致を確認した。ユーザーが起動画面・青いLED点滅・首の静止・異音と異常な発熱がないことを確認し、3回の電源入れ直しと10分間の継続動作でも異常がないと報告した。最小プログラムの初回合格条件は確認済み。復旧実演は未実施。最小プログラムはサーボ電源に無効化命令を送る構成。ビルド・転送・実機動作の状況は[検証記録](docs/verification/phase1.md)に分けて残す。

CoreS3向けのコンパイルと初回の転送検証に加え、起動画面・LED点滅・首が動かないことをユーザーの目視で確認した。サーボへの供給電圧は未測定。

AWSへのデプロイとMCPサーバーへの接続も未実施。
